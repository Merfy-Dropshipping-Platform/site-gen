# Места проверок

Владелец 16.11: проверки не должны лежать вразнобой — у каждой своё место, сегодня семантика, завтра Lighthouse.
Место выбирается по тому, что проверке нужно на входе. Схема и все шесть мест — страница «Каркас и проверки».

| Место     | На входе                               | Где живёт                            |
| --------- | -------------------------------------- | ------------------------------------ |
| `code`    | файлы секции                           | `storefront-sections` (приём секции) |
| `html`    | готовый HTML страницы, без браузера    | `checks/html/`                       |
| `browser` | открытая страница в Chromium           | `checks/browser/`                    |
| `audit`   | отдельный прогон страницы (Lighthouse) | пока нет                             |
| `shop`    | данные магазина перед публикацией      | пока в merfy-mcp `publish.ts`        |
| `release` | главная «до» и «после» выпуска         | `stand-check` (паспорт)              |

## Как устроено

- Одна проверка — один файл в папке места и свой тест: маленький HTML с ошибкой и без.
- Находка — один вид на все места: `CheckFinding` в `finding.ts`
  (`place`, `check`, `rule`, `level`, `section`, `where`, `text`, `count`). `text` — «что не так · как починить».
- Важность ставит проверка, последствие решает момент: семантика — всегда `warning`, публикацию не блокирует.
- Проверка находит по всей странице, отбор по секциям — `inSections`: в снимке секций — только изменённые секции
  (`sections` задания снимка = `checkScope` записи в sites), в снимке страницы — все.
- Проверка упала — это не находка, а `CheckFailure` с причиной; остальные проверки и снимок идут дальше.

## Что сейчас

- `html/semantic.ts` — html-validate: порядок и пустые заголовки, role вместо тега, кнопки и ссылки без текста,
  картинки без alt; своё правило `product-photo-alt` (фото товара с пустым alt).
- `browser/semantic.ts` — axe-core: ориентиры (header, main, footer), списки, недопустимые role, вложенные кнопки.

Запускает их снимок черновика (`look/look-job.ts`, поле `checks` ответа). Находки детектора и проверок вёрстки пока
идут прежним полем `findings` — переедут сюда отдельной задачей.

## Новая проверка

1. Файл в папке своего места: функция «вход места → `CheckFinding[]`», тексты по-русски.
2. Тест рядом с остальными (`__tests__/checks-*.test.ts`).
3. Вызов в раннере места: для `html` и `browser` — `checksOn` в `look/look-job.ts`.
   MCP менять не нужно: он показывает `checks` одним кодом.
