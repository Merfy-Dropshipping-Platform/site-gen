# @merfy/stand-check

Инструмент проверки стенда новой темы: паспорт страницы, сравнение двух прогонов, сценарии, отчёт и чек-лист
тестировщика. Стенд — служебная страница `/theme-stand` темы `nova`; покупателю она не видна и собирается только с
флагом `MERFY_THEME_STAND=1`. Проработка — `merfy-mcp/docs/plans/storefront-shell/02-stand/design.md`.

## Как запустить стенд

Нужен Node 24 и установленные зависимости: `pnpm install` в корне site-gen и `pnpm install --ignore-workspace` в
`themes/nova`.

```bash
pnpm --dir themes/nova stand
```

Команда собирает тему с флагом и поднимает `astro preview` на http://localhost:4321/theme-stand. Режим разработки
(`astro dev`) для прогонов не годится: он вставляет на страницу свои скрипты, и паспорт зашумит.

Во втором терминале, из корня site-gen:

```bash
pnpm --filter @merfy/stand-check stand:run --target local
```

Команда снимает паспорт стенда, прогоняет сценарии из `scenarios/`, сравнивает паспорт с эталоном
`baselines/local.json` и пишет отчёт. Код выхода: 0 — чисто или жёлтый; 1 — красный или сценарий не прошёл;
2 — команда не смогла выполниться (нет стенда, нет эталона, файл не прошёл схему).

Локально ответы API подменяются по таблице `mocks/routes.json` данными из `fixtures/`. Запрос к API, которого нет в
таблице, получает 501 и виден в паспорте. Прогон на dev (`--target dev`, адрес стенда — в `STAND_DEV_URL`) заработает
после блоков 4–6; почта и пароль покупателя там — только из `STAND_BUYER_EMAIL` и `STAND_BUYER_PASSWORD`.

## Как снять эталон

1. Запусти стенд и прогони `stand:run`; открой отчёт и посмотри глазами: отличия ожидаемые, чек-лист в порядке.
2. Запиши эталон:

```bash
pnpm --filter @merfy/stand-check stand:baseline --target local
```

3. Прогони `stand:run` ещё раз: должно быть «Чисто», код выхода 0. Закоммить `baselines/local.json`.

## Как читать отчёт

Отчёт лежит в `reports/<дата-время>/index.html` (папка не в git), рядом — оба паспорта прогона.

- **Чисто** — прогоны совпадают, сборка проходит.
- **Жёлтый** — отличия есть, сборка проходит; тестировщик смотрит их глазами. Так бывает после правки из панели: цвет
  поменялся — и так и надо.
- **Красный** — сборка не проходит, пока отличие не объяснят или не исправят: лишний скрипт, глобал `__MERFY_*__`,
  другой ключ корзины, ошибка в консоли.

У каждого отличия есть поле, что случилось (появилось, пропало, поменялось), было → стало и причина простыми словами.
Причины и серьёзность лежат данными в `compare-rules.json`. Внизу — чек-лист: сценарий, итог автомата, что смотреть
глазами и пустая колонка «ОК» для тестировщика.

Сравнить два любых паспорта:

```bash
pnpm --filter @merfy/stand-check stand:compare <a.json> <b.json>
```

## Проверка инструмента

Три поломки для приёмки — каждая обязана дать «Красный» и код выхода 1:

```bash
pnpm --filter @merfy/stand-check stand:run --target local --sabotage script
pnpm --filter @merfy/stand-check stand:run --target local --sabotage global
pnpm --filter @merfy/stand-check stand:run --target local --sabotage cart
```

Тесты, типы, линтер и формат — из папки пакета: `pnpm test`, `pnpm test:coverage`, `pnpm typecheck`, `pnpm lint`,
`pnpm format:check`. После правки схемы zod в `src/` — `pnpm generate:schemas`: JSON-схемы рядом с данными
пишутся только этой командой.
