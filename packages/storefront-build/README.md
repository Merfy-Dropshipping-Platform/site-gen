# @merfy/storefront-build

Ключ сборки и манифест магазина новой темы: сборка магазина — функция «входы → файлы + манифест». Одинаковые входы —
одинаковые файлы и ключ; изменили любой вход — другой ключ. Нынешние темы (rose, vanilla, flux, satin, bloom) и их
публикация этим пакетом не пользуются. Проработка — `merfy-mcp/docs/plans/storefront-shell/04-build-key/design.md`.

Пакет — исходники TypeScript без сборки. Хранилища, раздачи и очереди здесь нет: их делают блоки 5 и 6.

## Команды

Из папки пакета:

- `pnpm test`, `pnpm test:coverage` — быстрые тесты; порог покрытия — 80 %;
- `pnpm test:render` — тесты на настоящей серверной сборке темы `nova`: Astro собирает её перед тестами. Нужна
  установка темы: `pnpm install --ignore-workspace` в `themes/nova`;
- `pnpm typecheck`, `pnpm lint`, `pnpm format:check`;
- `pnpm probe` — проба рисовальщика: тема собирается дважды, файлы клиента и HTML двух сборок сравниваются, время
  страницы меряется на 400 запросах;
- `pnpm theme-version <тема>` — записать версию темы и отпечаток её файлов в `theme-versions.json`;
- `pnpm build:stand --out <папка> [--year <год>]` — магазин-стенд темы `nova` целиком: файлы сайта в `<папка>/files`,
  рядом `manifest.json` и `build.json`.

## Как устроено

- **Входы** (`src/inputs.ts`) — всё, от чего зависят файлы, одной схемой: хэш кода платформы, тема (версия и отпечаток),
  ядро и код секций (блок 7: `shell`, `code`), ревизия мерчанта, сайт, окружение, год и снимок данных. Снимок — целиком, с признаком
  `received`; иначе сборки нет. Сущности снимка — товары, коллекции, политики, контакты, публикации, касса.
- **Ключ** (`src/key.ts`) — хэш канонического JSON входов; данные входят картой «сущность → хэш». Коммит платформы в
  ключ не входит: это справка в манифесте.
- **Рисовальщик** (`src/theme-build.ts`, `src/renderer.ts`) — серверная сборка темы (`astro.renderer.config.mjs`,
  адаптер `@astrojs/node` в режиме middleware) один раз на версию темы. Страницы магазина лежат в `src/shop/` темы и
  берут данные только из `Astro.locals.merfy` (`src/locals.ts`). Vite при отрисовке не нужен.
- **Страница по запросу** (`renderShopPage`) — одна страница без полной сборки: строка в формате манифеста и файл.
  Полная сборка (`buildStorefront`) рисует каждую страницу так же.
- **Настройки темы и данные магазина** (`pagePropsOf`) — то, что страница даёт секциям с `"uses"`: настройки панели темы
  с правкой мерчанта и публичные данные магазина (`shop`). Значения считаются по полной панели платформы
  (`ShopTheme.platformPanel`): поле, которое тема скрыла в `theme.json → panel.hidden`, приходит с умолчанием, а правка
  по нему не действует; правки читаются по панели, которую тема показывает мерчанту (`ShopTheme.panel`).
- **Стенд в превью** (блок 8, `src/stand.ts`) — тот же рисовальщик рисует `/theme-stand` темы (`renderStand`) в
  `mode: preview` с правками мерчанта из ревизии: токены (`tokens`) и настройки не про вид (`settings`). Данные — в
  `Astro.locals.merfyStand` (`StandPageLocals`). Неподходящие правки стенд печатает списком и рисует без них.
  `previewTokens` — CSS токенов и атрибуты выборов для ручки `POST …/preview/tokens`; `PREVIEW_AGENT` — слушатель
  `update-tokens`, страница печатает его строкой. В сборку магазина стенд не входит: его нет в `SHOP_ROUTES`.
- **Манифест** (`src/manifest.ts`) — ключ, версии платформы и темы, карта сущностей, «путь → хэш файла» и строки
  страниц: чья страница (тип и `id` — для 301 и 410), от каких сущностей зависит (граф для `dependentPages`) и дата
  последней правки её данных (для `lastmod`). `build.json` пишется из манифеста, без времени сборки.

## Сторожа

- **Версия темы**: файлы темы изменились, а номер в `packages/theme-<тема>/theme.json` тот же, — тест красный.
  Подними `version`, потом `pnpm theme-version <тема>`. Какие файлы темы входят в отпечаток, — `THEME_FILES` в
  `src/render-files.ts`; новый файл темы без строки там тест «файл не учтён» не пропустит.
- **Код платформы**: тест «импорт не учтён» проходит по импортам `src/`; файл, до которого они дошли, обязан быть в
  `PLATFORM_RENDER_FILES`.
- **Рендер**: в `src/shop/` новых тем нельзя сеть, окружение, время, случайное, часовой пояс и язык процесса и чтение
  запроса (`src/render-guard.ts`). Год — вход `year`.
- **SEO**: у страницы есть язык, заголовок и канонический адрес `https://`, и она не больше 2 МБ (`src/seo.ts`);
  иначе ошибка `seo-contract`. SEO мерчанта (`site.branding.seo`) — во входах `site.description`, `site.seoTitle` и
  `site.keywords`: заполненное попадает в страницу, пустое сборку не валит. Заголовок — SEO-заголовок, иначе имя
  магазина, иначе адрес магазина (`src/head.ts`); имя в конфиге и на странице остаётся именем. Описание и ключевые
  слова мерчант может не заполнить — тогда тема не рисует `<meta name="description">` и `<meta name="keywords">`; тег
  без текста — ошибка. Теги для соцсетей (блок 9): по одному `og:title`, `og:type`, `og:url` с адресом `https://`,
  `og:site_name`, `og:locale` вида `ru_RU` и `twitter:card` (`summary` или `summary_large_image`); `og:description` и
  `og:image` — только с текстом и адресом `https://`, иначе без тега. Картинка — логотип из брендинга (вход
  `site.logoUrl`), если это PNG, JPEG, WebP или GIF по `https://` (`src/head.ts`).

## Как добавить вход

1. Поле — в схему `src/inputs.ts`, значение — в `fixtures/stand-inputs.json`.
2. Строка правки — в таблицу `EDITS` в `__tests__/key.test.ts`: тест «таблица правок покрывает каждый лист входов»
   без неё красный.
3. Поле — в `buildKey` (`src/key.ts`), если его нет в карте сущностей: тест «правка … меняет ключ» без этого красный.
4. Событие пересборки, которое меняет вход, — в `REBUILD_EVENT_INPUTS` (`src/event-inputs.ts`).

## Как добавить страницу

Пока страница одна — главная. Новая постоянная страница — строка в `SHOP_ROUTES` (`src/routes.ts`: адрес, файл, чья
это страница) и файл в `src/shop/pages/` темы; потом подними версию темы и запиши её (`pnpm theme-version <тема>`).
Страницы товаров и коллекций придут вместе с секциями.

## Код секций (блок 7; бандл страницы — блок 5 «Секций и SDK», часть 5б)

- Входы: `shell` — ядро секций `@merfy/shell` (`version`, `hash` — sha256 `dist/core.js`, `parts` — части из
  `core.json`), `null` — у входов стенда; `code` — секции магазина из таблицы секций (`storefront_section`): имя с
  префиксом автора, вид (`section` или `global`), хеш правки, разметка, стили и хеш скрипта; места — по id страницы,
  глобальные скрипты — списком. Код сверяется сам с собой (`code-invalid`).
- Страница: `head.codeHtml` — после токенов темы: `<style id="merfy-sections">` и тег бандла страницы; `sections` —
  разметка секций в `<merfy-section data-section="…">` по порядку мерчанта, у секции со скриптом последним элементом —
  `<script type="application/json" data-merfy-input>` (`src/input-tag.ts`, до 32 КБ). Тема печатает их как есть
  (`set:html`).
- Бандл страницы (`src/bundle.ts`, esbuild): ядро секций, части из `core.json` и часть `analytics`, модули секций
  страницы со скриптом и глобальные скрипты — один ES-модуль. До 4096 Б и без `</script`, `<!--` — в HTML, иначе файл
  `_merfy/b/<sha256>.js`: тот же набор секций — тот же файл. Модуль, на котором esbuild упал, пропускается
  (`section-script-skipped`), бандл тяжелее 100 КБ brotli — `page-script-heavy`; другая ошибка — `bundle-failed`.
  Превью, стенд и рендер без кода — без бандла.
- Байты — из `CodeAssets` (`readShellBuild` и скрипты из таблицы секций); нет их или байты не те — `shell-missing`,
  `shell-mismatch`, `code-missing` до рендера.
- Поведения и анимации (блок 6, часть 6б): в бандл попадают только поведения из `data-behavior` в HTML секций страницы
  (`header`, `sections`, `footer`) и в текстах их скриптов; `data-animate` — появления (`reveal`); слово `animate` в
  скрипте секции — провайдер для `ctx.animate`. Файлы — `packages/storefront-shell/dist/behaviors/` (`readShellBuild`
  читает `behaviors.json` и все файлы из него, `ShellBuild.kit`); хеш ядра во входах — по `core.js` и этим файлам. У
  страницы с `data-animate` в `<head>` перед бандлом — `<script>` с флагом `data-merfy-motion` и `<style id="merfy-motion">`
  (запасной показ через 3 с, если ядро не запустилось). Превью — все поведения (часть 6в, ниже). Нет страницы без поведений:
  вес бандла как в 5б.
- Превью конструктора (блок 5, часть 5г; `previewCode`, `src/preview-bundle.ts`): тега бандла страницы у превью нет —
  перед `</body>` HTML превью `<script type="application/json" id="merfy-preview-bundle">` со строкой бандла превью и
  `dist/preview.js` текстом (`ShellBuild.preview`, в хеш ядра не входит; нет файла — превью без кода). Бандл превью —
  секции всего кода магазина со скриптом, ядро с `watchPreviewReplace` (`start({ preview })`), без `analytics`: превью
  ничего не отправляет. Скрипт секций превью (`PREVIEW_SECTIONS_AGENT`) отдаёт правку секции с кодом скрипту превью
  (`merfy:preview:update`), рамку выбора ставит по `merfy:preview:updated`; сбой скрипта (`merfy:section:error`) —
  красная рамка и подпись «Ошибка в скрипте секции «…»: …»; кнопки и поля секции её не выбирают.
- Поведения в превью (блок 6, часть 6в; `previewKit`, `src/preview-kit.ts`): бандл превью — со всеми поведениями
  `ShellBuild.kit`, появлениями и провайдером `ctx.animate`, без разбора HTML страницы: мерчант может добавить слайдер
  на любую страницу. Флага `data-merfy-motion` у превью нет — появлений в превью нет. Выбор подпункта слева
  (`set-selection`) — `merfy:block:select { blockId }` на первом узле блока (`data-merfy-block`); другой блок или снятие
  выбора — сначала `merfy:block:deselect` прежнему; после `merfy:preview:updated` секции с выбранным блоком —
  `merfy:block:select` ещё раз.
- Ключ — версии 6: ядро секций и код входят целиком. Секции темы (`themes/<тема>/sections/`) — в хеше темы.

## Записи магазина (блок 8 «Секций и SDK», часть 8а-2)

- `src/records.ts`: товар, коллекция, блог, статья и политика из сущностей входов — запись с публичными полями
  (`RECORD_FIELDS`), адрес (`recordPath`, `recordSlug`: handle или id), SEO, зависимости страницы и дата правки.
  `recordIndexOf(entities)` — все записи сборки: по типу и id, по адресу, совпавшие адреса (`duplicates`).
- Цены — `Money` в копейках с текстом «1 900 ₽» (`money`); текст политики — HTML из абзацев (`policyTextToHtml`),
  список политик — `POLICY_PAGES` (его же читает `shop.policies`).
- Тип сущности `blog` (название и адрес); его меняет `publication-change`. Страниц записей в сборке пока нет — часть 8б.

## Страницы записей (блок 8 «Секций и SDK», часть 8б)

- `special-pages.json`: шаблоны записей `product`, `collection`, `blog`, `article`, `policy` — особые страницы с
  адресом-образцом (`/product/:slug`); заняты id шаблона и первая часть адреса (`SPECIAL_PAGE_SLUGS`: `/product`,
  `/collections`, `/blogs`, `/legal`).
- `src/routes.ts`: страница на каждую запись (`recordIndex`), если в списке шаблона есть видимая секция
  (`templateShown`); у политик — и с пустым шаблоном: в `<main>` текст от платформы (`src/policy-text.ts`, В8-1 А).
  Список страниц и индекс записей — один раз на входы; `routeDuplicates` — совпавшие адреса для журнала сборщика.
- Секции страницы записи получают `page.record` — публичные поля записи; у других страниц ключа нет, процесс рендера
  даёт `null`.
- Строка манифеста страницы записи: `entity` — запись, `deps` — записи страницы и сайт, `aliases` — адрес по id (301 на
  основной адрес — таблица раздачи). Страницы сборки рендерятся по `PAGE_CONCURRENCY` (8) за раз.
- SEO записи, превью шаблона с записью и дорисовка новой записи — часть 8б-2.

## SEO и превью страниц записей (блок 8 «Секций и SDK», часть 8б-2)

- SEO страницы записи (`src/head.ts`): заголовок и описание — `record.seo` (records.ts), ключевых слов нет; `og:type`
  — `product`, `article` или `website`; картинка — записи, нет — логотип магазина.
- `src/structured-data.ts`: JSON-LD `Product` страницы товара — в поле головы `structuredData`; цена — целые рубли,
  наличие — по записи; JSON экранирован для `<script>`.
- Конфиг витрины страницы записи — `page.record` (`{ type, id }`).
- Превью шаблонов: `routeOf(path, inputs, 'preview')` — страницы всех шаблонов и примеры платформы
  (`src/record-preview.ts`); сборка и рендер по запросу — режим `live`, без примеров. `previewRecordPath` — адрес
  записи шаблона по id или адресу, иначе запись по умолчанию; `pageInfoById(inputs, id, record)` — превью одного блока.

## Поля с записями в секциях (блок 8 «Секций и SDK», часть 8г)

- `src/section-records.ts`: виды полей и правила `data` (их читает пакет секций); `sectionRecords(placed, props)` —
  записи полей секции по `recordFields` экземпляра и индексу записей страницы (`PageProps.records`), их `deps` и
  `data` для тега входных данных; `menusWithRecordPaths` — ссылки меню на записи по id → основной адрес.
- Код секции во входах — `recordFields` (id настройки → вид) и `data`, только если объявлены: иначе входы и ключ
  прежние. Запрос рендера — ключ `records`; записи из полей — в `deps` строки страницы.
- Тег входных данных: `data` — объявленные поля записей, записи нет — `null`; предел 32 КБ — прежний.
- Скрипт превью (`src/preview-sections-agent.ts`, часть 8г-2): `page` и `record` из адреса превью — в теле запроса
  одного блока, так поля с записями и `page.record` в правке блока — те же, что у всей страницы превью. Адрес без
  параметров — тело прежнее.

## Особые страницы, 404 и 502 (блок 7 «Секций и SDK», часть 7а)

- Список особых страниц — `special-pages.json` (главная, «Страница 404»): постоянные id и адреса, заняты для своих
  страниц. Тот же файл читает sites: стартовая ревизия новой темы и меню страниц конструктора.
- `page = { id, path }` — в пропсах каждой секции, без `"uses"`; у страницы 404 `path: null`.
- `404.html`: у «Страницы 404» есть видимые секции — страница темы по адресу `/404`; нет — простая 404 платформы в
  цветах магазина. `502.html` — в каждой сборке, только CSS токенов. Строк страниц в манифесте у них нет.

## CSP витрин новых тем (блок 13 «Секций и SDK», часть 13б)

`src/csp.ts` — политика магазина по файлам сборки, адресам шлюза и сборщика аналитики, счётчикам и «своему коду»; поле
`csp` манифеста, дальше — таблица раздачи и заголовок раздачи у HTML (режим — `STOREFRONT_CSP` образа раздачи,
nginx-minio-proxy). Две политики: обычная — `'self'`, хеши флага движения и встроенного кода счётчиков, хосты счётчиков;
магазин со «своим кодом» — `'strict-dynamic'`, хеш файла бандла (у тега — `integrity`), запросы — `https:` и `wss:`.
Отчёты — `<analytics.url>/csp`. Длиннее 12 288 знаков — политики нет. Встроенные скрипты страниц оформления сборка
хеширует из их HTML (`src/inline-scripts.ts`, часть 15е), в `connect-src` — ещё хранилище файлов покупательницы
(`env.uploadUrl`); тест `__tests__/render/build.test.ts` краснеет на встроенном `<script>` без хеша.

## Каталог и страницы списка (блок 11 «Секций и SDK», часть 11а)

- Каталог — особая страница `catalog` (`/catalog`, `special-pages.json`): в сборке есть, когда в списке `catalog` есть
  видимый экземпляр; в превью — всегда. `shop.catalogUrl` — `/catalog` или `null`.
- Страницы списка — каталог, записи коллекций и блогов; страницы N — `…/page/N` (без «/» на конце), `…/page/1` — второй
  адрес первой страницы (301). Размер страницы — `per-page` первой сверху секции с этой настройкой, 2–24; нет — 24 товара
  или 12 статей. Список секции не на странице списка — товары поля `collection` этой секции (пусто — все товары),
  следующая страница — `?page=N`, её отдаёт рендер по запросу.
- `page.list` (`page-list.ts`) — у каждой секции страницы: карточки, `total`, номера, `prev`, `next`, выбранное (`query`),
  сортировки, значения фильтров. Параметры списка — `list-query.ts`: разбор, канонический вид, аргументы RPC
  `product.findAll` и `product.getFilters`, как у шлюза.
- Строка манифеста — `list: { page }` у страницы со списком; строка таблицы раздачи — `l: true`; в карте сайта страниц N
  нет. Страница с параметрами списка — `noindex, follow` и `meta[name=merfy-list]`.
- JSON вариантов (`page-variants.ts`) — `<script type="application/json" data-merfy-variants>` перед тегом бандла: товар
  страницы и товары полей `product`; больше 32 КБ — предупреждение `page-variants-heavy`.
