# Зонды замеров — общая библиотека

Каждый агент писал свой одноразовый `measure-*.mjs` и заново наступал на одни и
те же грабли. Только за 15.09 три разных агента независимо поймали одно и то же:
экранирование в собранном CSS, `\d` внутри шаблонной строки, отбор не того узла.
Знание уходило в чат, а не в репозиторий.

Здесь оно в репозитории. ТЗ агенту теперь звучит «прогони зонд на матрице», а не
«напиши замер».

---

## Быстрый старт

```bash
# какие цвета вообще лежат в схемах магазина (без этого «цвет чёрный» — не факт)
pnpm qa:probe schemes  --theme flux
pnpm qa:probe schemes  --url https://<стенд>.merfy.ru

# цвет мишени + ЦЕПОЧКА предков с их фонами
pnpm qa:probe color    --url https://<стенд>.merfy.ru --marker block:cart-body
pnpm qa:probe color    --theme flux --block Product --marker attr:data-cfg-name --prop color --scheme 1

# едет ли мишень за схемой: едет / замерла / НЕРАЗЛИЧИМО
pnpm qa:probe scheme   --theme bloom --block CartBody --marker block:cart-body \
                       --prop background-color --schemes 1,4 --role --color-bg
pnpm qa:probe scheme   --url https://<стенд>.merfy.ru/cart --marker block:cart-body \
                       --schemes 2,4 --role --color-bg

# есть ли класс в СОБСТВЕННОМ бандле темы
pnpm qa:probe phantom  --theme flux --class flux-container
pnpm qa:probe phantom  --theme bloom --block CartBody --marker block:cart-body

# геометрия (+ сравнение той же клетки с эталоном rose)
pnpm qa:probe geometry --url https://<стенд>.merfy.ru --marker css:.flux-container
pnpm qa:probe geometry --theme flux --block Product --marker css:.flux-container --vs rose

# открыть скрытое и ПРОВЕРИТЬ, что открылось
pnpm qa:probe reveal   --url https://<стенд>.merfy.ru --what search
pnpm qa:probe reveal   --url https://<стенд>.merfy.ru --what menu --width 375 --height 900
```

Маркер мишени: `block:cart-body` · `attr:data-cfg-name` · `attr:data-nt=promo-banner` ·
`#cart-title` · `css:.flux-container`. Старые формы из гардов (`data-block="cart-body"`,
`id="cart-title"`) тоже понимаются.

## Модули

| Модуль | Зачем |
| --- | --- |
| `tailwind-css.ts` | собранный CSS темы: экранирование имени класса, список классов бандла, «какая переменная стоит за утилитой» |
| `schemes.ts` | состав схемы магазина по ролям, РАЗЛИЧИМОСТЬ пары схем, снятие `tokens.css` с живого стенда |
| `markers.ts` | мишень по маркеру: селектор, ВСЕ совпавшие узлы, их классы |
| `render.ts` | живой рендер порта секции (та же лестница, что у витрины); без playwright |
| `bundle.ts` | победитель каскада в собранных бандлах (поверх общего `src/themes/__tests__/lib/css-cascade.ts`) |
| `stage.ts` | «сцена» замера: живой стенд или локальный рендер; опора ширины, высокое окно, http |
| `probes.ts` | цвет + цепочка предков, геометрия, переполнение, сравнение с эталоном |
| `follows-scheme.ts` | едет / замерла / неразличимо |
| `reveal.ts` | открыть поиск, дровер корзины, модалку «товар добавлен», мобильное меню — с проверкой |
| `report.ts` | таблица и ЧИСЛО проверенных клеток; ноль клеток — провал |

Движок каскада НЕ дублируется: `bundle.ts` — тонкая обёртка над
`src/themes/__tests__/lib/css-cascade.ts` (слои → специфичность → порядок → инлайн).

## Ловушки, зашитые внутрь (симптом → причина → как обходит зонд)

1. **Экранирование в собранном CSS.**
   Симптом: `grep` по имени класса даёт «0 вхождений», и это выглядит багом,
   которого нет. Причина: Tailwind печатает селектор экранированным —
   `.bg-\[rgb\(var\(--color-button-bg\,0_0_0\)\)\]`, запятая и скобки со слэшем.
   Обход: `classSelector()` экранирует имя ровно так же, поиск идёт по нему.

2. **Ведущая цифра в имени класса — это CSS-код символа.**
   Симптом: все утилиты брейкпоинта `2xl:` читаются как «класса нет в бандле»,
   зонд сам выдумывает классы-призраки. Причина: `2xl:px-[300px]` печатается как
   `.\32 xl\:px-\[300px\]` — код `\32` и пробел-терминатор. Обход:
   `classSelector()` кодирует ведущую цифру, `unescapeIdent()` её разбирает
   (поймано саботажем 15.09 — зонд поймал собственную ошибку).

3. **`\d` схлопывается в `d` внутри шаблонной строки.**
   Симптом: узлы «не находятся», хотя они в DOM. Причина: код, уезжающий в
   браузер строкой, теряет экранирование — `/^-\d+%$/` превращается в `/^-d+%$/`
   (то же с `\s`, `\w`). Обход: зонды передают в браузер ФУНКЦИИ, а не строки; на
   единственную дверь для сырого исходника (`evaluateSource`) повешен сторож
   `assertBrowserSource`, который на такую регулярку падает.

4. **Отбор узла по смыслу, а не «первый подходящий».**
   Симптом: у flux значок скидки лежит ВНУТРИ ссылки-превью, и отбор «первая
   непустая ссылка» возвращает превью вместо названия товара. Причина: замер без
   маркера. Обход: мишень адресуется только маркером; «первый подходящий» как
   способ отбора в библиотеке не предусмотрен.

5. **Граница имени атрибута.**
   Симптом: «плитка» мерится по ЛЕНТЕ. Причина: текстовая регулярка
   `data-cfg-thumb` ловит `data-cfg-thumbs-track`. Обход: узел ищется настоящим
   CSS-селектором по разобранной разметке — `[data-cfg-thumb]` с
   `data-cfg-thumbs-track` не совпадёт никогда.

6. **Маркер может совпасть с НЕСКОЛЬКИМИ узлами.**
   Симптом: саботаж мишени не красит гард. Причина: у flux «Товар» две ветки
   раскладки, `data-cfg-name`/`data-cfg-price`/`data-cfg-buy` стоят на обеих, а
   мерился первый. Обход: `nodesOfMarker`/`classesOfAllMarker` отдают ВСЕ узлы,
   зонды возвращают `matched`, CLI печатает «маркер неоднозначен».

7. **Красится не то, что видно.**
   Симптом: замер врёт в обе стороны. Причина: поле поиска прозрачно, а цвет
   несёт форма-обёртка. Обход: `probeColor` всегда возвращает ЦЕПОЧКУ предков с
   их фонами, первую непрозрачную заливку (`effective`) и того, кто красит
   (`painter`).

8. **Замер переполнения требует неподвижной опоры.**
   Симптом: «0 из 0», баг не виден. Причина: `window.innerWidth` растёт вместе с
   выходом за край. Обход: сцена помнит ЗАДАННУЮ ширину (`declaredWidth`), и
   `probeOverflow` считает от неё.

9. **Высота окна прячет баги раскладки.**
   Симптом: щель «не до конца» на окне 1000px = 22px, на 1400px = 422px.
   Причина: короткое окно. Обход: сцена после загрузки сама поднимает окно выше
   документа (`growTall`).

10. **Чёрно-белая схема не различает литерал и токен.**
    Симптом: ложное «замерла» либо ложное «закрыто». Причина: у satin Схема 1
    чёрно-белая — `#000000` и `rgb(var(--color-text))` дают одинаковые числа.
    Обход: `rolesDiffer()` сверяет пару схем по НУЖНОЙ роли ДО замера, и вердикт
    честно становится «неразличимо»; `pickDistinguishablePair()` подбирает пару,
    на которой вопрос решается.

11. **`Tests: 0 total` = exit 0.**
    Симптом: «ничего не проверено» выглядит как «всё хорошо». Причина: пустой
    прогон возвращает успех. Обход: `ProbeReport.finish()` печатает число
    проверенных клеток и возвращает 1, если клеток меньше минимума.

12. **Класс-призрак.**
    Симптом: конструктор показывает не то, что увидит покупатель. Причина: класса
    нет в СОБСТВЕННОМ бандле темы, а в превью его подменяет соседний из
    `preview-tailwind.css`. Обход: `phantomClasses()` считает по бандлу ТЕМЫ;
    `loadBundle(theme, { withPreview })` разводит два бандла явно.

13. **Вариант выигрывает у базового состояния.**
    Симптом: «фон кнопки» читается как цвет НАВЕДЕНИЯ. Причина: `hover:bg-[…]`
    объявлен позже обычного `bg-[…]`. Обход: `declaredVar()` пропускает классы с
    `:` (варианты) — меряется базовое состояние.

14. **Модульные скрипты не исполняются на `file://`.**
    Симптом: корзина пуста, дровер «не открывается» — похоже на баг темы.
    Причина: страница отдана через `setContent`. Обход: локальная сцена поднимает
    http-сервер и отдаёт страницу по нему.

15. **Неоткрытая панель меряется молча.**
    Симптом: цвета «скрытого» узла уходят в отчёт как факт. Причина: клик сочли
    успешным. Обход: `reveal()` после клика ПРОВЕРЯЕТ видимость панели числом
    (бокс, `opacity`, `visibility`) и возвращает `opened: false` с причиной;
    `revealOrThrow()` падает.

16. **Шторка спрятана СДВИГОМ, а не скрытием.**
    Симптом: дровер читается как «уже открыто» ещё до клика. Причина:
    `transform: translateX(100%)` оставляет и размер, и непрозрачность — на
    стенде satin панель стояла в `x = 1440` при окне 1440. Обход: проверка
    видимости требует ПЕРЕСЕЧЕНИЯ с окном раскладки
    (`documentElement.clientWidth/clientHeight`).

17. **Контейнер дровера видим всегда.**
    Симптом: «панель открыта» на любой странице. Причина: `[data-nt="cart-drawer"]`
    лежит поверх экрана постоянно, а выезжает вложенная `[data-cart-panel]`.
    Обход: в рецепте открытия контейнера нет — только выезжающая панель.

18. **Клик попадает в иконку, а не в кнопку.**
    Симптом: дровер корзины не открывается. Причина: клик по координатам
    попадает во вложенный `<svg>`. Обход: `reveal()` кликает сам управляющий
    элемент (`el.click()` в DOM) и дополнительно разрешает его `aria-controls` —
    у каждой темы шторка меню зовётся своим id.

19. **Блок без обёртки схемы не принимает схему НИКОГДА.**
    Симптом: мишень «замерла» во всех темах сразу. Причина: без пропа
    `colorScheme` `v2-page-composer` не оборачивает блок в `.color-scheme-N`.
    Обход: отдельный вердикт «нет обёртки схемы» вместо «замерла».

20. **`__name is not defined` в браузере.**
    Симптом: любой зонд падает под `tsx`. Причина: esbuild оборачивает функции в
    `__name(...)`, а Playwright сериализует функцию исходником. Обход: сцена
    ставит заглушку `__name` и на будущие переходы, и на открытую страницу.

## Чего библиотека НЕ делает

* Не пишет в живые сайты. На живом стенде схема переключается подменой класса
  обёртки в ЛОКАЛЬНОЙ копии DOM. Оборотная сторона честная: если тема красит
  секцию инлайновым стилем, посчитанным на сборке, подмена класса его не
  сдвинет, и зонд скажет «замерла» — такой случай видно по цепочке предков.
* Не чинит темы. Нашли баг — опишите построчно и оставьте.
* Не заменяет гарды. Гард остаётся гардом; библиотека убирает из него
  копипасту движка и калибровок.
