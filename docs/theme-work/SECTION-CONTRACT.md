# Контракт секции темы

Свод правил, которым обязана следовать секция любой темы Merfy, чтобы её настройки
в конструкторе действительно работали. Каждое правило родилось из реального бага —
рядом указано, как он выглядит для мерчанта.

Проверка: `node scripts/section-contract-check.mjs <тема>` (см. §12).

---

## 1. Приоритет поля = то, что показывает панель

Смотреть `/api/themes/<тема>/puck-config`:

| В панели | Порт обязан читать |
| --- | --- |
| top-level `headingSize` (select), а `heading` — строка | `p.headingSize ?? p.heading?.size` |
| `heading` — objectField с `size` | `p.heading?.size ?? p.headingSize` |

**Симптом нарушения:** мерчант выбирает размер, ничего не меняется. В старой ревизии
остался legacy-объект `heading.size`, и он молча глушит живой селект.

## 2. Пустая строка = «мерчант не задал»

```astro
// НЕЛЬЗЯ: ?? срабатывает только на null/undefined
const title = (p.heading ?? "Галерея");
// НАДО:
const title = (typeof p.heading === "string" ? p.heading : p.heading?.text)?.trim() || "Галерея";
```

**Почему:** платформа (`src/render/resolve-props.ts`) вычищает «незаданный» контент в
пустую строку. С `??` секция получает пустой `<h2>` вместо заглушки.

## 3. Заглушку видно в панели

Текст-заглушку объявить в `theme.json` → `blockPlaceholders`:

```json
"blockPlaceholders": {
  "Gallery": { "heading": "Галерея" },
  "Hero":    { "heading.text": "Изображение" }
}
```

Конструктор покажет его серым в инпуте. **Симптом нарушения:** на превью заголовок
есть, а поле пустое — мерчант не понимает, откуда текст и почему не может его убрать.

⚠️ Записывать заглушку в `blockDefaults` **нельзя** — платформа считает такие строки
незаполненным полем и вычистит их.

## 4. Секция сама ставит свою цветовую схему

```astro
const _rawScheme = p.colorScheme;
const _schemeId =
	typeof _rawScheme === "number" ? String(_rawScheme)
	: typeof _rawScheme === "string" && _rawScheme ? String(_rawScheme).replace("scheme-", "")
	: "";
const selfSchemeClass = _schemeId ? ` color-scheme-${_schemeId}` : "";
```

и на корневой элемент с `data-puck-component-id`.

**Почему:** при правке настройки превью перерисовывает ОДИН блок, обёртки композитора
в этот момент нет, и блок берёт `:root` — тёмную базовую палитру. Для мерчанта это
выглядит как «поменял одну секцию, а соседние сами перекрасились». На живом сайте
обёртка даёт ту же схему, дубль безвреден.

⚠️ Схема приходит **строкой ИЛИ числом** (нормализатор Slideshow приводит к номеру) —
проверка только на `string` молча не срабатывает.

## 5. Тумблер принимает boolean и строку

```astro
const show = p.agreement === true || p.agreement === "true";
```

**Симптом:** переключатель в панели не даёт эффекта (панель шлёт boolean, код сравнивал
со строкой).

## 6. Лестница размеров: канон внизу, ступени вверх, монотонно

- Дефолт панели (`defaultProps.<field>`) обязан попадать в **канон-ветку** — ту, что
  повторяет вёрстку верстальщика. Обычно это пустая строка классов.
- `small < medium < large` по фактическому кеглю.
- Заголовок не может стать мельче подзаголовка.

**Симптом:** «поменял заголовок — сбились стили». Дефолт панели попадал в ветку,
перекрывающую вёрстку, поэтому ЛЮБАЯ правка секции уводила её из канона.

## 7. Пользовательский текст — через `inlineFormat`

Кнопки «Ж»/«К» оборачивают значение в `<strong>`/`<em>`. Astro экранирует `{value}`,
поэтому:

```astro
<h2 set:html={inlineFormat(title)}></h2>
```

Плюс в `global.css` темы обязаны быть `strong,b { font-weight: 700 }` и
`em,i { font-style: italic }` — иначе `bolder` считается от лёгкой базы темы (300) и
жирный визуально неотличим.

⚠️ Внешний DS-компонент (`NtSectionHeading`) экранирует — нужна локальная копия
`ui/<Theme>SectionHeading.astro` с той же разметкой, импортируемая под тем же именем.

## 8. Перекрытие оформления вешать на существующий элемент

Перед тем как писать `[&_li>article>a]:aspect-[...]`, проверить, что такой узел реально
есть в разметке. Надёжнее — прокинуть значение пропом и поставить inline-стиль.

**Симптом:** класс в HTML присутствует, а размер/аспект не меняется — селектор не
совпал с разметкой (`li>article>div>a` вместо `li>article>a`).

⚠️ Проверять НЕ наличие класса в HTML, а computed-значение или bbox.

## 9. Настройка работает во всех путях рендера

Их три, и они расходятся:

1. SSR реальных данных (компонент карточки);
2. SSR плейсхолдера (пустое состояние);
3. клиентская гидрация (`renderCardHtml` и подобные).

Значение прокидывать во все три (обычно через `data-*` на контейнере для гидрации).
**Симптом:** в превью работает, на живом сайте нет — или наоборот.

## 10. Вёрстка верстальщика — это ОДНО из состояний, а не весь набор

Если настройка в rose даёт три поведения, в остальных темах она обязана давать те же
три. Чтобы не сломать дефолтный вид: **отсутствие пропа** = состояние вёрстки, **явное
значение** из панели применяется честно.

```astro
const mode = p.quickAddMode ?? "standard"; // нет пропа → как у верстальщика
```

## 11. Видимое поле панели приоритетнее скрытого legacy

`blockDefaults` темы часто задают legacy-поле (`align`), которое глушит видимый контрол
(`position`). Правило: если видимое поле задано — решает оно.

## 12. Ничего из панели не хардкодить

Если поле есть в панели — оно должно читаться. Fallback на литерал вёрстки допустим,
хардкод вместо чтения — нет. **Симптом:** правишь текст, ничего не меняется (так были
захардкожены заголовок и текст блока рассылки в подвале).


## 13. Подсекции проверять отдельно

Подсекций ДВА класса, и оба не покрыты `section-contract-check.mjs`:

1. **элементы списков** (ряд, колонка, слайд, пункт FAQ, плитка галереи) —
   поля `array` → `arrayFields`, прогон `scripts/subsection-fields-check.py`;
2. **именованные подсекции** («Заголовок», «Текст», «Кнопка», «Изображение»,
   «Варианты», «Объявление») — карта `NAMED_SUBSECTIONS` в конструкторе
   (`src/lib/utils/arrayField.ts`), индекс = 100 + позиция, открываются кликом
   по элементу в превью; прогон `scripts/named-subsection-check.py`.

⚠️ Проверять именованную подсекцию нужно, ВОСПРОИЗВОДЯ `defaultProps` темы: legacy-поле
из дефолтов (`button.href`, `textSize`) глушит видимое поле панели (`button.link`,
`text.size`) — так нашлись два нарушения §11. Без дефолтов баг не воспроизводится.

⚠️ И наоборот, ложные «мёртвые» получаются, если у object-поля не заполнить соседние
подполя («Размер» на пустом заголовке, «Ссылка» на кнопке без текста), не дать блоку
картинку (уходит в ветку заглушки) или взять для `Product` товар без вариантов.

Поля ВНУТРИ ряда, колонки, слайда, пункта и элемента галереи (`array` → `arrayFields`)
`section-contract-check.mjs` **не проверяет** — тип `array` в его SKIP_TYPES. Их гоняет
`scripts/subsection-fields-check.py`: для каждого array-поля собирается элемент, блок
рендерится с двумя элементами и проверяются две вещи — что каждый элемент выбираем
(число маркеров `data-puck-subsection-field` = числу элементов) и что каждое поле
элемента живое.

**Симптом:** мерчант открывает ряд/слайд и правит поле — ничего не меняется, хотя
на уровне секции всё работает.

⚠️ Проверять только РЕАЛЬНЫМИ картинками: пути `/placeholders/*` и `/images/4x/*` порты
считают «не выбрано» (`contentSet` / `slotImage`), и поле выглядит мёртвым ложно.

⚠️ Маркер на КОНТЕЙНЕРЕ списка (индекс 997, например `Header.navigationLinks`) — не
нарушение: такие списки правятся модалкой целиком.

## Как проверять

```bash
# статические правила по коду портов темы
node scripts/section-contract-check.mjs bloom

# + прогон всех полей через рендер и сверка с эталонной темой
node scripts/section-contract-check.mjs bloom --runtime --baseline rose
```

Рантайм-режим меняет каждое видимое поле панели на два разных значения и сравнивает
HTML: если рендер не изменился — настройка мертва. Сверка с эталоном отделяет реальные
отставания от общих особенностей платформы.

⚠️ Базовые пропсы в прогоне заполняются текстом и включёнными тумблерами — иначе
«Размер текста» меряется на секции без текста и живое поле выглядит мёртвым.

⚠️ Проверяя hover-эффекты каталога в браузере, берите ВИДИМУЮ карточку
(`getBoundingClientRect().width > 0`). У каталога две раскладки — верхняя и боковая —
и обе лежат в DOM: у невидимой размеры 0×0, а код честно выходит по `if (!rect.width)
return`. Проверка на скрытой карточке даёт «настройка не работает» на полностью
исправном коде. Из 4 карточек с доп. фото видимыми оказались 2.

⚠️ Атрибуты `data-img-primary/secondary/2/3/4` проставляет КЛИЕНТСКИЙ `renderCardHtml`,
в SSR их нет ни у одной темы — через `POST /preview/block` режимы наведения не
проверить. И превью на :3114 тоже не годится: его клиент ходит на прод-gateway,
и при недоступном проде гидрация не проходит, а грид пустой. Смотреть надо в
конструкторе (:3200), где apiBase локальный.

⚠️ Прогон подставляет условия, без которых живая настройка выглядит мёртвой:
товар С ВАРИАНТАМИ в блок «Товар», картинку в поля-изображения И внутрь элементов
списков (аспект применяется только в ветке медиа-бокса), включает `boolean`-флаги
вроде `banner.enabled` (без него узел не рендерится). Тумблеры включаются ВСЕ,
кроме `hide*` — включённый «Скрыть заголовок» прячет текст, и правка текста
перестаёт что-либо менять. Судить о таких тумблерах по подписи нельзя: у подвала
показ рассылки подписан «Скрыть/показать».

⚠️ Настройки, которые не применяются НАМЕРЕННО, перечислены в `INTENTIONALLY_INERT`
внутри скрипта — с причиной каждой. Они печатаются отдельным разделом и не считаются
нарушением. Список нужен, чтобы отчёт оставался коротким: длинный отчёт из ложных
срабатываний перестают читать, и в нём теряются настоящие поломки.

⚠️ Поля вариаций товара проверяются только на сайте, где есть товар с НЕПУСТЫМИ
`variantGroups`/`variantSwatches`/`variantCombinations`. Флаг `hasVariants` бывает
выставлен и без самих данных — прогон это учитывает и такие поля пропускает.

## Порядок пересборки

| Что правил | Что выполнить |
| --- | --- |
| `themes/<t>/src/components/sections/*.astro` | `node scripts/compile-theme-sections.mjs <t>` |
| вложенный компонент (`products/*.astro`) или `lib/*.ts` | то же **+ перезапуск sites** (модуль висит в кэше импортов Node) |
| новые arbitrary-классы Tailwind | ещё и `npx tsx theme-registry/_build-theme.ts <t>` |
| `theme.json`, контроллеры `src/**` | `npx nest build` + перезапуск sites |

## Платформенное правило «поле не заполнено» (исправлено 2026-09-07)

Раньше `src/render/empty-state.ts` считал незаполненным полем целые слова —
«коллекция», «кнопка», «заголовок», «видео», «публикации». Мерчант вводил «Видео» в
заголовок, `resolve-props.ts` вычищал текст, и секция показывала заглушку: правка
«исчезала». Работало это только в превью, поэтому превью расходилось с витриной.

Теперь «не задано» = **пусто ИЛИ ровно дефолт блока**. Дефолты берутся из
`<Block>PuckConfig.defaults` (`src/render/block-defaults.ts`, с кэшем) и мержатся с
`blockDefaults` темы; словарь служебных слов в этой ветке больше не участвует
(`isBlankContent` вместо `isUnsetContent`).

Поведение:

| Что в данных | Результат |
| --- | --- |
| мерчант ввёл «Видео» | рендерится «Видео» |
| поля нет / пустая строка | заглушка темы |
| значение ровно как дефолт блока | заглушка темы (как раньше) |
