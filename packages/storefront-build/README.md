# @merfy/storefront-build

Ключ сборки и манифест магазина новой темы: сборка магазина — функция «входы → файлы + манифест». Одинаковые входы —
одинаковые файлы и ключ; изменили любой вход — другой ключ. Нынешние темы (rose, vanilla, flux, satin, bloom) и их
публикация этим пакетом не пользуются. Проработка — `merfy-mcp/docs/plans/storefront-shell/04-build-key/design.md`.

Пакет — исходники TypeScript без сборки. Хранилища, раздачи и очереди здесь нет: их делают блоки 5 и 6.

## Команды

Из папки пакета:

- `pnpm test`, `pnpm test:coverage` — быстрые тесты; порог покрытия — 80 %;
- `pnpm test:render` — тесты на настоящей серверной сборке темы `nova`: Astro собирает её перед тестами. Нужна
  установка темы: `pnpm install --ignore-workspace` в `themes/nova`;
- `pnpm typecheck`, `pnpm lint`, `pnpm format:check`;
- `pnpm probe` — проба рисовальщика: тема собирается дважды, файлы клиента и HTML двух сборок сравниваются, время
  страницы меряется на 400 запросах;
- `pnpm theme-version <тема>` — записать версию темы и отпечаток её файлов в `theme-versions.json`;
- `pnpm build:stand --out <папка> [--year <год>]` — магазин-стенд темы `nova` целиком: файлы сайта в `<папка>/files`,
  рядом `manifest.json` и `build.json`.

## Как устроено

- **Входы** (`src/inputs.ts`) — всё, от чего зависят файлы, одной схемой: хэш кода платформы, тема (версия и отпечаток),
  каркас (блок 7, пока `null`), ревизия мерчанта, сайт, окружение, год и снимок данных. Снимок — целиком, с признаком
  `received`; иначе сборки нет. Сущности снимка — товары, коллекции, политики, контакты, публикации, касса.
- **Ключ** (`src/key.ts`) — хэш канонического JSON входов; данные входят картой «сущность → хэш». Коммит платформы в
  ключ не входит: это справка в манифесте.
- **Рисовальщик** (`src/theme-build.ts`, `src/renderer.ts`) — серверная сборка темы (`astro.renderer.config.mjs`,
  адаптер `@astrojs/node` в режиме middleware) один раз на версию темы. Страницы магазина лежат в `src/shop/` темы и
  берут данные только из `Astro.locals.merfy` (`src/locals.ts`). Vite при отрисовке не нужен.
- **Страница по запросу** (`renderShopPage`) — одна страница без полной сборки: строка в формате манифеста и файл.
  Полная сборка (`buildStorefront`) рисует каждую страницу так же.
- **Стенд в превью** (блок 8, `src/stand.ts`) — тот же рисовальщик рисует `/theme-stand` темы (`renderStand`) в
  `mode: preview` с правками мерчанта из ревизии: токены (`tokens`) и настройки не про вид (`settings`). Данные — в
  `Astro.locals.merfyStand` (`StandPageLocals`). Неподходящие правки стенд печатает списком и рисует без них.
  `previewTokens` — CSS токенов и атрибуты выборов для ручки `POST …/preview/tokens`; `PREVIEW_AGENT` — слушатель
  `update-tokens`, страница печатает его строкой. В сборку магазина стенд не входит: его нет в `SHOP_ROUTES`.
- **Манифест** (`src/manifest.ts`) — ключ, версии платформы и темы, карта сущностей, «путь → хэш файла» и строки
  страниц: чья страница (тип и `id` — для 301 и 410), от каких сущностей зависит (граф для `dependentPages`) и дата
  последней правки её данных (для `lastmod`). `build.json` пишется из манифеста, без времени сборки.

## Сторожа

- **Версия темы**: файлы темы изменились, а номер в `packages/theme-<тема>/theme.json` тот же, — тест красный.
  Подними `version`, потом `pnpm theme-version <тема>`. Какие файлы темы входят в отпечаток, — `THEME_FILES` в
  `src/render-files.ts`; новый файл темы без строки там тест «файл не учтён» не пропустит.
- **Код платформы**: тест «импорт не учтён» проходит по импортам `src/`; файл, до которого они дошли, обязан быть в
  `PLATFORM_RENDER_FILES`.
- **Рендер**: в `src/shop/` новых тем нельзя сеть, окружение, время, случайное, часовой пояс и язык процесса и чтение
  запроса (`src/render-guard.ts`). Год — вход `year`.
- **SEO**: у страницы есть язык, заголовок и канонический адрес `https://`, и она не больше 2 МБ (`src/seo.ts`);
  иначе ошибка `seo-contract`. SEO мерчанта (`site.branding.seo`) — во входах `site.description`, `site.seoTitle` и
  `site.keywords`: заполненное попадает в страницу, пустое сборку не валит. Заголовок — SEO-заголовок, иначе имя
  магазина, иначе адрес магазина (`src/head.ts`); имя в конфиге и на странице остаётся именем. Описание и ключевые
  слова мерчант может не заполнить — тогда тема не рисует `<meta name="description">` и `<meta name="keywords">`; тег
  без текста — ошибка.

## Как добавить вход

1. Поле — в схему `src/inputs.ts`, значение — в `fixtures/stand-inputs.json`.
2. Строка правки — в таблицу `EDITS` в `__tests__/key.test.ts`: тест «таблица правок покрывает каждый лист входов»
   без неё красный.
3. Поле — в `buildKey` (`src/key.ts`), если его нет в карте сущностей: тест «правка … меняет ключ» без этого красный.
4. Событие пересборки, которое меняет вход, — в `REBUILD_EVENT_INPUTS` (`src/event-inputs.ts`).

## Как добавить страницу

Пока страница одна — главная. Новая постоянная страница — строка в `SHOP_ROUTES` (`src/routes.ts`: адрес, файл, чья
это страница) и файл в `src/shop/pages/` темы; потом подними версию темы и запиши её (`pnpm theme-version <тема>`).
Страницы товаров и коллекций придут вместе с секциями.
