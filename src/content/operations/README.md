# Движок операций над документом магазина

Этап 2 «Безопасная запись», кусок 2.1. План: `merfy-mcp/docs/plans/2026-09-24-stage2-safe-write.md`.

Чистые функции без базы данных:

| Функция | Что делает |
|---|---|
| `diff(base, next) → Op[]` | операции, которые превращают `base` в `next` |
| `apply(doc, ops) → doc` | применяет операции к копии документа |
| `paths(ops) → string[]` | адреса операций без повторов |
| `readAt(doc, path)` | значение по адресу (`undefined`, если места нет) |
| `merge3(base, current, incoming, policy)` | трёхстороннее слияние: `{ merged, overwritten[], conflicts[], applied }` |

Главное свойство, которое сторожат генеративные тесты на золотых документах пяти тем:
`apply(a, diff(a, b))` равен `b`.

## Адрес поля

Адрес — строка сегментов через `/`. Секции и страницы адресуются по id, а не по индексу
массива: перестановка секций не превращает правку в «удалить + добавить». Один и тот же
адрес пишется в `meta` ревизии, возвращается в ответе записи и (потом) принимается
инструментами агента.

| Адрес | Что это |
|---|---|
| `page:home/block:Hero-1/props/heading/text` | поле секции `Hero-1` на главной |
| `page:home/block:Hero-1` | секция целиком (добавить, убрать, заменить) |
| `page:home/order` | порядок секций страницы — одно поле |
| `page:home/root/props/title` | свойства страницы |
| `page:home/zone:Columns-1:left/block:Text-1/props/text` | секция внутри зоны |
| `page:home/zone:Columns-1:left/order` | порядок секций в зоне |
| `page:page-about` | содержимое страницы целиком (`pagesData`) |
| `pages/page-about` | мета страницы целиком (элемент `pages[]`) |
| `pages/page-about/name` | поле меты страницы |
| `pages/order` | порядок страниц |
| `themeSettings/colorSchemes` | настройка темы |
| `currentPageId`, `lockVersion` | служебные поля |

Правила:

- Любой вложенный объект разбирается поле за полем. Любой массив, кроме списков секций и
  страниц, — одно значение: слайды, пункты меню, цветовые схемы.
- Если список секций где-то не годится для адресации по id (повтор id, секция без id), он
  сравнивается целиком: `page:home/content`. То же для `pages` и зон.
- Экранирование — как JSON Pointer плюс двоеточие: `~` → `~0`, `/` → `~1`, в ключах
  `:` → `~2`. Буквальный ключ `order` пишется `~3order`. Внутри id с префиксом двоеточие
  остаётся как есть (`zone:Columns-1:left`).
- Форма документа описана данными в `shape.ts`: какие массивы — списки с id, какие
  объекты — словари, какие контейнеры «подняты» в адрес родителя.

## Операции

```json
{ "op": "set",    "path": "page:home/block:Hero-1/props/heading/text", "value": "Новый" }
{ "op": "remove", "path": "page:home/block:Gallery-1" }
{ "op": "add",    "path": "page:home/block:Text-7", "value": { "type": "MainText", "props": { "id": "Text-7" } }, "after": ["Hero-1", "Header-1"] }
{ "op": "order",  "path": "page:home/order", "ids": ["Header-1", "Gallery-1", "Hero-1", "Footer-1"] }
```

- `add.after` — соседи слева, ближний первым. Вставка идёт после первого, который есть в
  документе; если нет ни одного — в начало. Цепочка переживает удаление соседа другим
  писателем.
- `order.ids` — порядок элементов, которые были и до, и после правки. Применяется «по
  слотам»: чужие новые элементы остаются на своих местах.
- `remove` отсутствующего ничего не делает. `set` или `add` в место, которого нет
  (например, поле в удалённой секции), — ошибка `apply_target_missing`.

## Слияние

`merge3(base, current, incoming, policy)`:

- `base` — версия, от которой сделана входящая правка;
- `current` — что лежит в магазине сейчас;
- `incoming` — что прислал пишущий.

Правки в разных местах сливаются. Спорное место — наименьший адрес, где чужая и входящая
операции пересекаются (с учётом поднятых контейнеров: `page:home/content` содержит
`page:home/block:Hero-1`). Если значения сторон там совпали, спора нет.

| Политика | Кто | Спорное место |
|---|---|---|
| `last-writer-wins` | сохранение конструктора, откат | побеждает входящая; удалённая другим секция возвращается на своё место, если в ней правили; чужое значение — в `overwritten` |
| `reject-conflicts` | черновики, API-операции | ничего не сливается, `merged = null`, список — в `conflicts` |

- Страница — одна единица при споре «страница целиком»: мета `pages/<id>` и содержимое
  `page:<id>` берутся с одной стороны.
- В `overwritten`/`conflicts` попадают только места, которые чужая сторона действительно
  меняла. Отсутствующее значение — `null`.
- Служебные поля `currentPageId` и `lockVersion` спорами не бывают: берётся входящее
  значение, если входящая сторона его меняла.
