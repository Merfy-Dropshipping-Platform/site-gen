# Свои сторы

> SDK 1 · документация 1.37.0 · 2026-11-12

Свой стор — значение JSON, которое считает код автора отдельно от секций: «покупатель собирается уйти», «город
покупателя», «окно уже показывали». Секции и другие сторы его читают, меняет только код самого стора. Места на странице
у стора нет, шаблона тоже.

## Файлы стора

Стор — папка с двумя файлами: `section.json` с `"kind": "store"` и `script.ts`. Проверка, сохранение и публикация — те
же адреса и тот же путь, что у секции ([start.md](start.md), [path.md](path.md)).

```json
{
  "sdk": 1,
  "name": "exit-offer",
  "kind": "store",
  "title": "Предложение перед уходом",
  "uses": ["cart", "store:shop:visits"]
}
```

```ts
import { defineStore } from '@merfy/shell';

export default defineStore({
  value: false,
  start(ctx, set) {
    ctx.watch(ctx.stores['shop:visits'], (visits) => set(typeof visits === 'number' && visits > 2));
  },
});
```

- `value` — значение до запуска и для страницы, где `start` ещё не дошёл до `set`. JSON: `null`, булево, число,
  строка, список, объект.
- `start(ctx, set)` — запуск на странице, один раз. `set(value)` — новое значение; не JSON (`Date`, `NaN`, экземпляр
  класса) — сбой стора.
- Ключей места (`groups`, `limit`, `role`, `wrapper` и других) у стора нет; в `uses` — модули SDK, `ext:<id>` и сторы,
  без `theme` и `shop`: шаблона нет, читать их негде. `template.astro` у стора нет, скрипт — `script.ts` или `script.js`.
- `export default defineStore(…)`. `defineSection` в сторе и `defineStore` в секции — отказ
  [`kind-mismatch`](errors.md#kind-mismatch).

## ctx стора

Как у секции ([script.md](script.md#ctx)), без того, что связано с разметкой (`ref`, `refs`, `on`, `animate`, `state`,
`data`):

| Член | Что делает |
|---|---|
| `ctx.stores['<префикс>:<имя>']` | стор из `uses`, читается через `ctx.watch` |
| `ctx.watch(store, fn)` | подписка на стор: сразу текущее значение, потом каждое новое |
| `ctx.listen(name, fn)` | событие витрины `merfy:…` или событие секции `<имя секции>:<событие>` |
| `ctx.emit(name, detail)` | своё событие, уходит как `<имя стора>:<name>` |
| `ctx.every(ms, fn)` / `ctx.after(ms, fn)` | повтор и один раз через `ms` |
| `ctx.storage` | хранилище стора в браузере: `get`, `set` (до 4 КБ), `remove`; своё у каждого стора |
| `ctx.<модуль>`, `ctx.ext.<id>` | модули SDK и расширения из `uses` — как у секции ([modules.md](modules.md)) |
| `ctx.page`, `ctx.mode`, `ctx.theme`, `ctx.log` | страница, `live` или `preview`, настройки темы, вывод в превью |

`window`, `document`, `fetch`, `setTimeout`, `localStorage` — нельзя, как в скрипте секции: всё через `ctx`.

## Как читать стор

`"uses": ["store:<префикс>:<имя>"]` в `section.json` секции, глобального скрипта или другого стора. Имя — полное: стор
магазина — `store:shop:exit-offer`, стор расширения — `store:<id расширения>:<имя>`. В скрипте:

```ts
mount(el, ctx) {
  ctx.watch(ctx.stores['shop:exit-offer'], (show) => ctx.ref('offer')?.toggle(show === true));
},
```

Стор в `ctx.stores` — только для чтения: у него есть `get()` и подписка `ctx.watch`, записать в него нечем. Чтение
`ctx.stores['…']` без строки в `uses` — отказ [`store-unknown`](errors.md#store-unknown).

## Кто что читает

| Код | Читает |
|---|---|
| магазина (`shop:…`) | свои сторы и сторы включённых расширений |
| расширения `<id>` | только свои сторы: `store:<id>:<имя>`; данные магазина — через модули SDK |

- Стор расширения — в манифесте расширения, список `storefront.scriptStores`, рядом с `storefront.sections` и
  `storefront.globals`; поставляется так же, как секции расширения.
- Код расширения со стором другого автора в `uses` — отказ [`store-foreign`](errors.md#store-foreign).
- Стор неопубликован или его расширение выключено — сборка идёт, у секции, которая его читает, на витрине сбой
  `part-unknown`, остальная страница работает.

## Порядок запуска и круг

- Стор попадает в бандл только тех страниц, где его читает стоящая на странице секция, глобальный скрипт или другой
  такой стор. Лишний стор в `uses` — лишний код на каждой странице с этой секцией.
- Сторы запускаются до секций, по зависимостям: стор — после сторов, которые он читает. Секция в `mount` уже видит
  значение.
- Стор, который через другие сторы читает сам себя (`shop:a` читает `shop:b`, а `shop:b` — `shop:a`), не сохраняется:
  отказ [`store-cycle`](errors.md#store-cycle) с кругом в тексте. Общее для двух сторов вынеси в третий стор, который
  читают оба.

## Сбой стора

Ошибка в `start`, в подписке или таймере стора, `set` не JSON — страница работает дальше. Таймеры и подписки стора
снимаются, значение остаётся последним — секции читают его как прежде. На странице — событие `merfy:section:error`
с именем стора в `section` и `id` ([events.md](events.md)), в консоли — строка «Сбой стора <имя>».

## В превью

Стор работает и в превью конструктора; `ctx.storage` там — в памяти вкладки, в браузер покупателя ничего не пишется.
Новую секцию, которая читает стор, которого ещё нет в превью, стор догоняет после перезагрузки превью.
